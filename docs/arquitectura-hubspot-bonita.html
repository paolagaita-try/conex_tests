Integración HubSpot ↔ Bonita

Ticket en HubSpot → caso en Bonita · round robin · cada transición BPMN se refleja como stage del ticket

Entrada (ticket → caso)

  • • Free/Starter: webhook de app ticket.creation + middleware externo
  • • Ops Hub Pro: custom code action dentro de HubSpot (sin servidor)
  • • Idempotencia por ticketId (no duplica casos si reintenta)
  • • La base de Bonita es idéntica en ambos — decide Laura/líder

Núcleo Bonita

  • • Proceso BPMN: 1 caso por ticket, con rutas de retorno
  • • Round robin: service task Groovy + contador en BDM
  • • Conectores REST nativos de salida (no el conector Beta)
  • • Runtime Tomcat + H2 (:8096), build Maven -Pbundle

Riesgos / a congelar

  • • Versión de API: fijar 2026-09 vs v3 (no mezclar)
  • • Contrato de IDs: mapa estado Bonita → stageId (falla silenciosa si deriva)
  • • Webhooks requieren app pública + Developer API key (no Private App)
  • • Token secreto: nunca en el repo ni en argumentos
